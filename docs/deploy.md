# 遠隔対戦を動かす

離れた2人がブラウザで対戦するための手順。**手元だけで完結する遊び方**と、
**Vercel に上げて外から遊べるようにする手順**の2つがある。

---

## 1. 手元で動かす（Vercel は要らない）

```
npm run build     # public/index.html を作る（React ごと1枚に埋め込む）
npm run serve     # http://localhost:5173
```

同じ機械の2つのタブでも、同じ Wi-Fi の別の機械（`http://<このPCのIP>:5173`）でも遊べる。
保存先はメモリなので、**サーバを止めると部屋は消える**。

遊び方は3通り:

| やりたいこと | 手順 |
|---|---|
| 2人で対戦 | 片方が「部屋を作る」→ 出た**合言葉**を相手に伝える → 相手が「合言葉で入る」→ 両者デッキを選んで準備完了 |
| 1人で試す | 「AI と対戦する」にチェックして部屋を作る（相手の席は AI が打つ） |
| 自作デッキ | `npm run builder` で作ったデッキのテキストを、入口かロビーの「持ち込み」に貼る |

同じブラウザの2つのタブで別々の席に座れる（席の控えはタブごとに持っている）。
リロードしても同じ席に戻る。タブを閉じてしまっても、入口の**「さっきの席に戻る」**から戻れる。

---

## 2. Vercel に上げる

**この作業は本人にしかできない**（アカウントが要る）。私の側では本番の確認ができないので、
下の手順を踏んで、うまくいかない箇所を教えてほしい。

### ① Upstash Redis を用意する（部屋の保存先）

Vercel の関数は**呼び出しをまたいで何も覚えていない**ので、部屋を置く場所が要る。

1. <https://upstash.com> でアカウントを作り、Redis データベースを1つ作る（無料枠で足りる）
2. データベースの画面で **REST API** の2つの値を控える
   - `UPSTASH_REDIS_REST_URL`
   - `UPSTASH_REDIS_REST_TOKEN`

保存されるのは**部屋1件につきキー2本**だけ:

```
room:<合言葉>      部屋まるごと（設定・選択の列・両者のビュー）
room:<合言葉>:v    版番号だけ    ← ポーリングはこれしか読まない
```

どちらも24時間で自動的に消える（触るたびに延びる）。

### ② Vercel に繋ぐ

1. <https://vercel.com> でこのリポジトリを Import する
2. Environment Variables に ① の2つを入れる（Production / Preview の両方）
3. Deploy する

設定は `vercel.json` に入っている（ビルドは `npm run build` だけ）。
**環境変数が無いまま Vercel で動かすと、部屋を作った直後に「無い」と言われる状態になる**ので、
その場合はわざとエラーで止まるようにしてある。

#### 成果物は自分で組み立てて渡している

`npm run build` は `.vercel/output/`（Build Output API v3）を作る。

```
.vercel/output/
  config.json                      経路（/api/* 以外は index.html へ）
  static/index.html                対戦画面
  functions/api/<name>.func/
    .vc-config.json                ランタイム（nodejs22.x）
    index.mjs                      esbuild で1ファイルに束ねた関数
```

関数の入口は **`server/functions/*.ts`** に置いてある。ここが要点で、
**リポジトリの根に `api/` があると Vercel が自動検出して自前でビルドしてしまい、
上の成果物が使われない**。

Vercel が自前でビルドすると、`api/game.ts` は**その1ファイルだけ**が JS に変換される。
このリポジトリは ESM なので Node は拡張子を補完せず、`../src/net/routes` を
実行時に解決できずに関数が起動前に落ちる（`ERR_MODULE_NOT_FOUND` →
ブラウザには `FUNCTION_INVOCATION_FAILED`）。実際に2度踏んだ。

`tools/build-vercel.test.ts` が「束ねた結果に相対 import が残っていないこと」と
「束ねたものを読み込んで実際に応答が返ること」を毎回確かめている。

> Vercel の Project Settings に **Output Directory** が入っている場合は空（既定）に戻すこと。
> `.vercel/output` があるときはそれが使われるが、設定が残っていると紛らわしい。

### ③ 動作確認

先に、経路が生きているかを直接見るのがはやい。

| 開くURL | 期待 | 違ったら |
|---|---|---|
| `/api/ping` | `{"ok":true, ...}` | 関数の仕組み自体が動いていない（Vercel の Runtime Logs を見る） |
| `/api/v?room=TEST` | `{"room":"TEST","version":null}` | `error` に理由が出る。環境変数の入れ忘れ・再デプロイ忘れが多い |

そのうえで:

1. 発行された URL を開いて「AI と対戦する」で部屋を作る → 数手打てること
2. 別のブラウザ（or スマホ）で開いて、合言葉で入って2人対戦

`api/ping.ts` は切り分け用の探針で、リージョンと Node の版、
**環境変数が入っているかどうか（値は出さない）**だけを返す。要らなくなったら消してよい。

### あとで Vercel Postgres に移すとき

保存しているのは**素の JSON 1件**、書き込みは
「版が一致したときだけ書く」（`compareAndSet`）**1操作だけ**に閉じてある。
`src/net/store.ts` の `RoomStore` を実装したクラスを1本足して、
`src/net/store.factory.ts` の分岐に加えれば移せる（部屋のロジックは触らない）。

Postgres 側は1行の `jsonb` と

```sql
UPDATE rooms SET doc = $1, version = $2 WHERE id = $3 AND version = $4
```

で足りる。

## 3. 費用の考え方

Vercel は**実行時間**で課金されるので、経路を3つに分けてある。

| 経路 | 何をするか | エンジン | 1試合あたり |
|---|---|---|---|
| `GET /api/v` | 版番号だけ返す | 回さない | 数百〜千回（軽い） |
| `GET /api/state` | 保存済みのビューを返す | 回さない | 版が動いた回数だけ |
| `POST /api/game` | 選択を足して**再生し直す** | 回す | 選択の回数だけ |

対戦の実体は「選択の列」で、盤面は**選択が入ったときにだけ**頭から再生して作り直す
（`src/net/resume.ts`）。実測は `npm test` の「費用」テストが毎回出す:

```
1試合: 自分の選択 18件 / 記録 33件（AI 15件）/ 再生 34回 / ポーリング 95回 / 合計 205ms（1再生あたり 6.0ms）
```

**1試合まるごとで 0.2 秒**。ポーリングは何度来ても版番号を読むだけなので、ここには乗らない。
上限（合計10秒）を割ったらテストが落ちる。

画面側でも問い合わせを減らしてある:

- 相手を待つ間隔は 1秒 → 3秒 → 5秒と広げる
- **タブが隠れているあいだは止める**（表に戻った瞬間に1回だけ行く）
- 自分の手番のあいだは15秒に1回の心音だけ（応答を取りこぼしたまま固まらないため）
- 選択を送った応答に新しい盤面が入っているので、送信直後は問い合わせない

## 4. 隠された情報について

サーバは `GameState` をそのまま配らない。`src/engine/view.ts` が
**見せてよいものだけを組み立てる**（削るのではなく積む）。相手の手札・山札・予知領域・
伏せた勝利条件に加えて、**乱数の内部状態**（以後のシャッフルが読める）、
`limitUses` のキー（伏せた勝利条件のIDが出る）、`events[].bindings` や `snapshots`
（引いたカードが特定できる）も外に出ない。`src/engine/view.test.ts` が
「ビューのJSON文字列にそれらが現れないこと」を毎回確かめている。
